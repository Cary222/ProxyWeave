# ProxyWeave Architectural Decision Records (ADR)

本文档归档 ProxyWeave 自立项以来的 7 项关键架构决策。每项决策均经过真实开源项目源码审计、平台兼容性推导与方案权衡。

> **权威完整论证**：详细推导与架构分析请参见项目根目录 [Plan.md](../../../Plan.md#10-架构决策记录-adr---architectural-decision-records) 及 [docs/PLAN-ProxyWeave.md](../../PLAN-ProxyWeave.md#10-架构决策记录-adr---architectural-decision-records) 第 10 章节。

## 决策索引清单

### [ADR-01: 为什么选择成熟脚手架 (Quotio) 改造而非从零手写桌面外壳？](../../../Plan.md#adr-01-为什么选择成熟脚手架-quotio-改造而非从零手写桌面外壳)
- **背景**：原方案试图从零编写 Tauri 2.0 桌面外壳、托盘、窗口生命周期、自启动与系统凭证库。
- **决策**：采用成熟的 `xiaocoss/quotio-desktop`（MIT License，commit `21d75d08`）作为主脚手架基线。
- **核心权衡**：Quotio 已经成熟实现了跨平台桌面托盘、单实例锁、系统 Keyring (1192 行平台代码)、IDE 配置读写等极其繁琐的工程细节。将其中的特定平台业务（Codex/Kiro）剥离并重构为通用插件宿主，比从零研发节省至少 3 周时间且稳定性大幅提升。

### [ADR-02: 为什么借鉴 TiyGate 协议与路由设计而非全盘照搬商业网关？](../../../Plan.md#adr-02-为什么借鉴-tiygate-协议与路由设计而非全盘照搬商业网关)
- **背景**：需要抹平 OpenAI Chat、Responses 与 Anthropic Messages 之间的流式与协议差异。
- **决策**：将 `tiylabs/tiygate`（Apache-2.0，commit `6db40e54`）作为协议层首要参考源，借鉴其 IR 中间表示与编解码器，但坚决不引入其 SQLx 数据库与商业计费模块。
- **核心权衡**：TiyGate 拥有高品质的 Rust 原生多协议转换算法。只提取协议编解码模块，可最大化利用其流式状态机，同时保持 ProxyWeave 的本地极简无库特色。

### [ADR-03: 为什么选择微内核黑盒独立进程，而非动态链接库 (DLL/so) 或 WebAssembly？](../../../Plan.md#adr-03-为什么选择微内核黑盒独立进程而非动态链接库-dllso-或-webassembly)
- **背景**：插件运行形式的技术选型。
- **决策**：坚持黑盒可执行进程模型。
- **核心权衡**：各类开源反代项目技术栈异构严重（Go、Rust、Node.js、Python）。动态链接库存在语言 ABI 冲突且单一崩溃会导致宿主同归于尽；Wasm 目前无法运行重型 Go 运行时及复杂系统 Socket。黑盒独立进程具备天然的内存隔离与故障边界。

### [ADR-04: 为什么废除纯 LRU 淘汰，改为四象限生命周期与 Singleflight 互斥锁？](../../../Plan.md#adr-04-为什么废除纯-lru-淘汰改为四象限生命周期与-singleflight-互斥锁)
- **背景**：原方案采用强制限制 1~2 个进程并按 LRU 杀死。
- **决策**：引入四象限策略、`active_requests` 活跃引用计数与 Singleflight 冷启动锁。
- **核心权衡**：LLM 会话长流式可能持续数分钟。按 LRU 杀死进程会导致正在进行的会话被腰斩；突发高并发请求命中休眠插件会导致重复拉起与端口碰撞。

### [ADR-05: 为什么严禁在异常断开时盲目追加 `data: [DONE]`？](../../../Plan.md#adr-05-为什么严禁在异常断开时盲目追加-data-done)
- **背景**：部分简陋网关为了强行闭合 SSE 流，在遇到任何网络断开或上游报错时均追加 `[DONE]`。
- **决策**：补发终止符必须具有协议层正常完成证据（HTTP 200 + 上游包含合法 `finish_reason` 的尾帧）；异常截断时坚决不补发 `[DONE]`。
- **核心权衡**：当上游报错或网络截断时追加 `[DONE]`，下游代码编辑器（如 Cursor）会误判为生成完整并直接应用残损代码，导致严重的工程事故。各协议必须遵守其各自规范（OpenAI 为 `[DONE]`，Anthropic 为 `message_stop`）。

### [ADR-06: 为什么采用系统级凭证库/分离式加密，而非明文 JSON 存储 Secret？](../../../Plan.md#adr-06-为什么采用系统级凭证库分离式加密而非明文-json-存储-secret)
- **背景**：凭据保存的安全性考量。
- **决策**：使用 `keyring-rs` 对接系统安全凭据管理器，与常规 JSON 配置物理分离。
- **核心权衡**：个人电脑常面临恶意插件或同机脚本扫描普通配置目录的风险。将 Secret 托付给 OS 原生安全体系是桌面软件的行业标准规范。

### [ADR-07: 为什么将“成熟实现直接复用优先”确立为强制性工程研发纪律？](../../../Plan.md#adr-07-为什么将-reference-first-确立为强制性工程研发纪律)
- **背景**：AI 编程助手容易脱离工程实际盲目手写脆弱机制，或在阅读参考代码后重新生成一份同质代码并谎称“复用”。
- **决策**：将“成熟实现直接复用优先 (Direct Reuse First)”确立为强制纪律，按“直接依赖 -> 模块提取 -> 薄适配 -> 必要修改 -> 自研（须 ADR 审批）”顺序执行。
- **核心权衡**：系统底层机制充满平台边缘陷阱，经过实战检验的成熟模块稳定性远超 AI 重新生成的代码。AI 的核心价值在于检索比对、提取适配与定位修复，不默认重写已有成熟算法。
